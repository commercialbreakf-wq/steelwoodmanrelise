# Spec: Admin Pro 2026 - High-Performance Management System

## 1. Overview
**Goal:** Replace the 2800-line monolithic `admin.html` with a modern, modular, and high-performance management system.
**Scope:** Product management, bulk operations, smart price-list synchronization, and basic dashboard for leads/orders.

## 2. Architecture
- **Frontend:** Modular Vanilla JS (or lightweight React/Angular if preferred, but given current codebase, Modular Vanilla JS with a component-based approach is most idiomatic). Let's go with **Modular Vanilla JS** to stay close to the project's performance-first philosophy.
- **Backend:** Node.js (Express) + Supabase (Postgres + Auth).
- **Caching:** Proactive Client-Side Cache + Server-Side In-Memory Cache with granular invalidation.
- **Authentication:** Supabase Auth with `authenticateAdmin` middleware.

## 3. UI/UX Design
- **Layout:** Hybrid (Sticky Sidebar + Sortable Table + Side Drawer).
- **Interactions:** 
  - Clicking a row opens the Side Drawer for deep editing.
  - Hover actions for quick status toggles.
  - Multi-select for bulk actions.
- **Optimistic UI:** Changes reflect in the UI immediately, with background synchronization and error toast notifications.

## 4. Key Features
### 4.1. Smart Sync Engine
- **Input:** Markdown or Excel files.
- **Logic:** "Intellectual Merge" - updates only `price` and `status` based on matching `vid` or `name`, preserving manually enriched fields (description, images, special specs).
- **Feedback:** Summary report before applying changes (optional toggle for auto-apply).

### 4.2. Bulk Actions Manager
- **Price Adjustment:** Apply ±X% or ±Amount to selected items or categories.
- **Category Migration:** Batch move items to different hierarchy levels.
- **Status Toggle:** Quick Enable/Disable/Out-of-Stock for batches.

### 4.3. High-Performance API
- **Endpoint:** `POST /api/admin/bulk-update`
- **Transactional:** All-or-nothing updates for bulk operations to ensure data integrity.
- **Cache Hook:** Triggers targeted cache invalidation in `api/[...slug].js` instead of full `warmProducts()`.

## 5. Success Metrics
- **Initial Load:** < 500ms (Gzipped).
- **Bulk Update (100 items):** < 1s to reflect in DB + Cache.
- **Developer Experience:** Clear separation of concerns (API vs UI vs Logic).
