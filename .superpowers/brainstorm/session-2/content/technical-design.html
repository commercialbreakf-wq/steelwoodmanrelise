Техническая архитектура и Потоки данных

Обеспечение "бесшовности" и надежности при массовых операциях

Схема взаимодействия компонентов
Frontend (Admin Panel)
● Local State: Мгновенное обновление UI до ответа сервера
● Bulk Dispatcher: Пакетная отправка изменений
● Side Drawer: Изолированный редактор сущности
⇆
Backend (Express + Supabase)
● Atomic Updates: Транзакционное изменение групп товаров
● Cache Invalidation: Точечное обновление In-Memory кэша
● Import Engine: Парсинг MD/Excel в фоновом режиме

Принято: реализуем полный набор инструментов

Что это даст администратору:

  • Мгновенность: Цена изменилась в таблице? Она уже в базе и в кэше.
  • Безопасность: Отмена действий (Undo) для массовых правок.
  • Автоматизация: Загрузили новый прайс — система подсветила изменения перед сохранением.

Вопрос №3: Как должна работать синхронизация из прайс-листа (Markdown/Excel)?

Выберите наиболее подходящий сценарий "бесшовности"

A

Полуавтомат (Рекомендуется)

Вы загружаете файл, система показывает список: "10 цен изменилось, 2 новых товара". Вы нажимаете "Применить".

B

Полный автомат

Загрузили — база обновилась мгновенно. Максимальная скорость, но меньше контроля над ошибками в файле.

C

Интеллектуальное слияние

Система обновляет только цены и наличие, не трогая вручную отредактированные описания и фото в админке.
